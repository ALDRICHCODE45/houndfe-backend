## Specs

- **S1 Command.** `pnpm seed:showcase` runs `scripts/dev-showcase/seed.cjs`, which runs the domain modules in order (base check → org → catalog → commerce → ops). It requires the base seed (`pnpm seed`) and refuses to run when `NODE_ENV=production` or when the database URL host is not local/dev (explicit `SHOWCASE_ALLOW=1` override). Re-running creates nothing new (match by natural keys / readable names, upsert).
- **S2 Language and names.** «Todo en español de México, con nombres realistas y legibles, sin ids en los nombres.» Prices in MXN, business timezone America/Mexico_City; dates relative to "today" so the data stays fresh on every run (e.g. route started today, lot expiring in < 7 days).
- **S3 Coverage matrix (verbatim from L1).** Every bullet of L1's matrix is a requirement: users/roles/branches; >30 products with every stock/lot/variant/service/image/long-name/category/brand/price-list case; kardex >30 movements on one product incl. OPENING, INITIAL, each adjustment reason (OTHER with note), a FEFO sale split across 2 lots, a cancellation and a REMOVAL; sales in every payment/delivery/refund state spread across the month; >15 customers; quotations in every state; promotions of every type × active/scheduled/ended, one nearly exhausted limit, one unlimited; cash registers/sessions/movements/pending custody handover; human decisions pending/approved/rejected/expired; delivery routes draft (no driver or no stops), active today with delivered/current/skipped stops, completed, cancelled; suppliers (one archived) and POs ready / missing cost / missing quantity / reference issue / confirmed / cancelled; HR active/on leave/terminated employees, expired and expiring documents, pending time-off (single and multi-day); admin payment methods (one inactive) and bank accounts (one active, one inactive); notification config with modules on/off; catalog config with public lists and a publication; public catalog «Disponible», «Pocas piezas», «Agotado».
- **S4 Write path.** Stock must go through the inventory journal (INITIAL on create, adjustments, real sale charge/cancel) so the kardex is consistent; prefer the real services/HTTP API for stateful flows (sales, cancellations, PO confirm, routes), direct Prisma only where no API exists. Never bypass tenant scoping.
- **S5 README.** «Documentalo en el README (qué crea, cómo correrlo y los usuarios de prueba con su rol, sin poner passwords en el chat).» Section in `README.md` (and link from `docs/frontend-handoff/README.md` §7).
- **S6 Run + cleanup now.** «Corrélo también ahora sobre la DB de dev y borrá la basura de pruebas («Prueba T8 …», «zz sale probe», «Online (dev)»).» The dev DB is disposable (human, L2).
- **S7 Verification.** After running on dev, report counts/states per screen through the GET endpoints; re-run proves idempotence (no new rows).
