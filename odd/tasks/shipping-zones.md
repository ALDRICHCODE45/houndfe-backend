# Shipping quotes and delivery zones (backend)
Branch `feat/shipping-zones` (this worktree, `.tmp/shipping-proposal`). Design: `docs/shipping-and-delivery-zones-proposal.md` (read it fully; §1, §4, §5, §9–§11 are binding).
First step: T1 zones, T2 packaging, T3 quote engine (no carrier credentials). Later: Skydropx adapter, chatbot contract (quotes endpoint, shipping {quoteId|mode:"pickup"} in checkouts/sales).

## Specs
- S1 Zones per postal code per sucursal, types FREE / SURCHARGE / CARRIER_ONLY / DENIED; "Todo junto": approving a zone decides whether it is delivered, its type, the surcharge when SURCHARGE and the zone's usual delivery days.
- S2 Unknown postal code → pending validation reusing human-decisions with a new type DELIVERY_ZONE, idempotent per postal code and sucursal; bot intake fields: zipCode, state, municipality, neighborhood, customer phone, conversation reference, last customer message time; outcome: final zone status plus surcharge and ETA when they apply; bot learns it via the existing intake/poll/outcome cycle.
- S3 Email to users with permission (new NotificationActionKey DELIVERY_ZONE_VALIDATION_REQUESTED, React Email template) stating the 24 h deadline; store UI list of pending validations sorted by last customer message time with urgency near 24 h ("Urgencia + plazo"). Permission to validate: `DeliveryZone:validate` (plus read/manage zones for the store UI).
- S4 Packaging data: package weight (g) and dimensions (cm) of the packed item per product, overridable per variant — "peso en gramos y dimensiones en cm del paquete armado, no el peso neto editorial".
- S5 Standard boxes per sucursal (name, inner dimensions, own weight, max weight); sucursal origin address with postal code. "Un paquete por pedido": total weight = Σ package weight × qty + box weight; smallest box that fits; none fits → clear error.
- S6 Quote engine with carrier ports and fake adapters: "Siempre se usa la MÁS BARATA"; quotes every configured carrier, cheapest among those that answered, tie → shorter ETA; one carrier failing uses the other; all failing → SHIPPING_QUOTE_UNAVAILABLE; missing packaging → PACKAGING_DATA_MISSING listing products.
- S7 Credit: "$120 MXN por artículo de más de $500" counted "Por unidad" with unit price after discounts from repricing the cart with the customer's price list/promotions; credits sum; customer pays max(0, cost − credit). Applies to carrier cost AND own-zone surcharge — POR CONFIRMAR by the owner, so it must be one configurable rule.
- S8 Signed quote with expiry (30 min default, never beyond carrier validity), bound to sucursal, customer, cart lines, destination; checkout errors SHIPPING_QUOTE_NOT_FOUND / SHIPPING_QUOTE_EXPIRED / SHIPPING_QUOTE_MISMATCH (wiring into checkouts/sales is S4-later).
- S9 Delivery time "Base + ajustes": zone usual days; if an item lacks sellable stock the quote returns eta {days:null, reason:"STOCK_PENDING"}; staff can set an adjusted estimated delivery date on a specific sale with a reason and the bot is notified.
- S10 DENIED → "Recoger en tienda": sale without shipping (`shipping: {mode:"pickup"}`) — contract part of later S4.
